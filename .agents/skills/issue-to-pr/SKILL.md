# Issueから統合PRを作成する

`$issue-to-pr #123`のように対象のIssue番号を受け取る。以下の`#N`はその番号を表す。各工程で指定した`SKILL.md`を読み、その手順と完了条件に従う。再開時は登録済みの子Issue、統合PR、コミット、作業ツリーを照合し、最初の未完了工程から続ける。

1. **子Issueを登録する**

   `$to-tickets #N`で分割案を作る。案は自動承認し、そのまま子Issueと依存関係をGitHubに登録する。すでにある子Issueと依存関係は再利用し、不足分だけ登録する。[to-ticketsの手順](../to-tickets/SKILL.md)

2. **実装を1つの統合PRにまとめる**

   `$implement-spec #N`に同じIssueを仕様として渡し、PR作成を指定する。元の作業ツリーに別件の変更があれば、統合ブランチ用のworktreeを分ける。子Issueの実装を同じ統合ブランチに取り込み、前提となる実装がすべてそろった子Issueから着手する。子Issueがない場合は指定Issue自体を実装する。[implement-specの手順](../implement-spec/SKILL.md)

   統合PRがあれば再利用する。新規の場合は最初の実装を取り込んでプッシュした時点で、`main`向けのドラフトPRを開く。本文で親と子の各Issueを`Closes #番号`で関連付け、子Issueの実装を取り込むたびに同じ統合ブランチをプッシュする。全実装と`implement-spec`内の`code-review`を終えたら、修正を含む統合ブランチの先端をプッシュしてからPRをレビュー可能にする。以降はそのPRのheadブランチの作業ツリーで進める。

3. **実装差分をレビューして修正する**

   `~/.codex/skills/claude-review/SKILL.md`に従い、`$claude-review main..HEAD`を実行する。Codexと読み取り専用のClaude Codeが実装差分をレビューし、採用した指摘はCodexが修正する。検証と双方の再レビューまで同スキルの手順に従う。

4. **最初のレビュー後にコミット・プッシュする**

   レビューによる修正があれば、その変更をステージし、日本語のメッセージでコミットする。統合ブランチの未プッシュのコミットを同じPRのheadブランチにプッシュする。

5. **差分ファイルに変異テストを実行する**

   手順4を終えた`HEAD`で、`~/.codex/skills/mutant-test/SKILL.md`に従って`$mutant-test main..HEAD`を実行する。差分に含まれる本体ファイル全体を対象に、必要な修正と再測定まで行う。対象ファイルが0件ならその旨を記録する。修正は未ステージ・未コミットのまま次へ渡す。

6. **変異テスト後の未コミット変更をレビューする**

   引数なしの`$claude-review`で、手順5で生じた未コミット変更を新規ファイルも含めてレビューする。対象が0件ならその旨を記録する。採用した指摘は未コミットのまま修正・検証し、変異テストの結果に影響があれば手順5と同じ対象を再測定する。修正後は双方で再レビューする。

7. **最終結果をコミットし、同じPRに反映する**

   手順5・6で残った変更があれば、まとめてステージし、日本語のメッセージでコミットする。同じ統合ブランチにプッシュし、レビュー可能な統合PRの先端がローカルの`HEAD`と一致することを確認する。

親・子Issue、統合PRのURL、プッシュしたコミットを示し、2回のレビュー結果と変異テストの前後比較を各スキルの形式で報告する。
