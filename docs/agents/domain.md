# ドメイン文書

このリポジトリはsingle-context構成を使用する。

## 探索前に読む文書

- ルートの`CONTEXT.md`: ドメインの概念と用語。
- `docs/adr/`: 作業対象に関係する設計判断。

文書が存在しない場合は、そのまま作業を進める。
不足の報告や事前作成の提案は不要。
用語や設計判断が実際に確定した時点で、
`domain-modeling`スキルが必要な文書を作成する。

## 配置

- `CONTEXT.md`
- `docs/adr/NNNN-<判断の名前>.md`

## 用語の統一

Issueのタイトル、リファクタリング案、仮説、テスト名などでは、
`CONTEXT.md`で定義された用語を使用する。

必要な概念が未定義の場合は、既存の用語で表せるかを確認する。
実際に定義が不足している場合は、`domain-modeling`で扱う事項として記録する。

## ADRとの整合

提案が既存ADRと矛盾する場合は、
対象ADRと、判断を見直す理由を明示する。
