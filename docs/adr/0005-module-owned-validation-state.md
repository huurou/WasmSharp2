# 同じモジュールに検証成功と実行表現を保持する

2026-09-06の`wasm-runtime-foundation`の設計確認で、`Validate()`は同じ`WasmModule`を返し、検証が成功した場合だけそのモジュールに実行表現を保持する方式を採用した。定義は外部から変更できなくし、途中で失敗した実行表現はインスタンス化に利用できないようにする。

同日の追加確認で、検証済み状態は`WasmModule`の`isValidated_`フラグで管理し、`ValidatedModule`のような検証済み専用クラスは設けないことを確定した。フラグは初期状態と検証失敗時には`false`とし、実行表現が完成して検証が成功した場合だけ`true`にする。検証済みのモジュールへの再度の`Validate()`は、再検証や実行表現の再生成をせず、同じモジュールを返す。

検証済みの別クラスを返す案に対し、既存の4段階の利用形を保ち、状態を表すクラスを増やさないことを優先した。その代わり、検証前の`Instantiate()`は型で禁止するのではなく、実行時の契約違反として拒否する。検証と線形化は同一パスとし、検証済みモデルと実行モデルを二重保持しない[ADR 0002](0002-single-pass-linear-interpreter.md)の方針を維持する。
