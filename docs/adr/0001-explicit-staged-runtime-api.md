# Wasmの4段階と明示的な値・型を公開契約にする

2026-09-06のdiscoveryで、入力の破損・検証不成立・リンク不成立・trap・未実装を説明できることをライブラリの価値とし、Decode→Validate→Instantiate→Invokeと段階ごとの例外型を維持する方針を採用した。値はWasmValueで渡し、ホスト関数型を明示宣言し、object/dynamicの汎用引数・CLR型からの暗黙変換・delegate型の推論・4段階を畳むローダーを持たない。便利な自動変換をライブラリが用意する案に対し、Wasm仕様にない変換・切り詰め規則の維持義務を作らないことを優先する。

対象仕様の未実装はWasmUnsupportedFeatureExceptionで区別し、実装の不足を検証失敗にしない。Instantiate中のstartや初期化のtrapはリンク不成立と区別し、失敗が起きた段階と原因を混同しない。具体的な型の割り当てと公開APIの引数・戻り値は後続のdesignで確定する。

公式ランナーも通常の利用者としてspectestを公開APIだけで構成する。検証のためだけの裏口を作る案を避け、APIの追加は通常利用にも意味がある能力に限る。
