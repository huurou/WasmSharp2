# Core 2.0のバイナリ適合を固定した公式テストで完成させる

2026-09-06のdiscoveryで、初期の完了目標をCore 2.0のバイナリ・検証・実行への適合とし、Core 3.0は将来の別計画にすることをユーザーが選択した。Core 1.0限定ではSIMD等を含められず、3.0から始める案ではGC等の追加設計とWABTの変換対応不足を同時に扱う必要があるため、SIMDを含む2.0を先に完成させる。3.0へ拡張できる構成を保つが、型体系や公開契約を無変更で移行できる保証はしない。

WASTを自前で解析する案に対し、wast2jsonで分解し、自作ツールはJSONと`.wasm`だけを読む方式を採用する。仕様版・公式入力集合・変換器・生成物・全feature状態を固定し、対象内は未実装でもON、対象外はOFF、`--enable-all`は禁止とする。実装進捗でフラグを変えると入力と合格集合を比較できなくなるため、更新は実装の進捗と分離して追跡する。

変換器が出力するテキスト構文エラー用の`.wat`等は対象外として記録し、開かず、合格件数に含めない。変換できない入力はツール不成立であり、ランタイム未実装を観測したことにはしない。3.0への拡張時も2.0の固定素材と結果baselineを残し、否定テストの期待値まで両版で同じだとは扱わない。

仕様・ツールの確認根拠と未実行の検証項目は[discovery調査](../research/wasm-runtime-discovery.md)に記録する。具体的な固定commit・実効CLI・配布物は公式テスト素材の仕様で確定する。
