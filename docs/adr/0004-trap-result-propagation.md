# 内部trapを実行結果で返し、ホスト境界で例外へ変換する

2026-09-06のdiscoveryで採用したtrapの扱いを、[ADR 0002](0002-single-pass-linear-interpreter.md)から独立した判断として記録する。内部trapは列挙型の実行結果で返し、ホスト境界の共通の1箇所だけでWasmTrapExceptionへ変換する。InvokeだけでなくInstantiateからのstart実行にも同じ変換処理を適用する。

.NET例外で実行ループを抜ける案に対し、trapのたびに.NET例外を投げるコストを避ける目的で実行結果による伝達を選んだ。これは性能の数値保証ではない。この判断は線形化や検証パスの構成に依存せず、trapの扱いだけを将来見直す際に、それらの判断を変更する必要はない。

受け入れる不利益は、例外による自動的な脱出の代わりに、実行結果を返す補助処理の呼び出し側がtrapを確認し、正常処理を継続せず結果を返す責任を持つことである。確認漏れがあるとtrap後も処理が続くため、結果を受け取る箇所の扱いを揃える必要がある。診断に必要なWasmの実行位置や呼び出し情報も、例外を生成するだけでは得られないため、実行結果の付加情報と保持方法を後続のdesignで確定する。
