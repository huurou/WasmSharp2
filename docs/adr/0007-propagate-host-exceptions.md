# ホスト処理の例外をそのまま伝播する

2026-09-06の`wasm-runtime-foundation`の設計確認で、ホスト処理が投げた.NET例外は専用の例外でラップせず、そのまま利用者へ伝播する方針を採用した。元の例外の型と実体を維持し、ホスト側の既存の例外処理で扱えるようにする。これは後続のホスト連携が使う共通契約であり、基盤にホスト呼び出しの実装を追加する判断ではない。

専用の例外でラップすればホスト由来の失敗を型だけで識別できるが、今回は元の例外をそのまま扱うことを優先した。ホストが`WasmTrapException`などのランタイムの例外型を投げた場合もそのまま伝播するため、その型だけで発生元を必ず区別できるとは保証しない。ホスト例外を内部のtrap結果やリンク不成立へ変換しない。

[ADR 0004](0004-trap-result-propagation.md)の、内部trapを実行結果で返して共通ホスト境界で例外へ変換する方式は維持する。この変換はランタイムが検出したtrapに適用し、ホスト処理から投げられた例外の伝播とは分ける。
