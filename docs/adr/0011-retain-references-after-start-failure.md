# start失敗後もホストが保存した参照を有効に保つ

startを実行する前に、ランタイムとして必要なinstanceの構築、importの照合・接続、リソースの割当・初期化を完了する。start中のホストcallbackへinstanceを渡せることは、この構築が済んでいることを示すが、Instantiateの成功を証明しない。

startが失敗した場合はInstantiateを例外で終了し、完了済みの副作用を戻さず、ホストが保存したinstance・関数・リソースを自動的に無効化しない。参照を失効させる案では、既に共有された関数やリソースも含めた状態管理が必要になるため、実体を有効に保つ方針とする。

保存済みの参照から引き続き操作できるが、startによる初期化の完了は保証しない。その状態で処理を続けるかはホスト側が判断する。後続のdata/element初期化も同じInstantiate経路を使い、各仕様で複合挙動を検証する。
