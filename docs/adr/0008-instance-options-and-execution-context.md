# インスタンスの実行ポリシーでコンテキストを開き、最外側の上限を固定する

2026-09-06の`wasm-runtime-foundation`の設計確認で、実行オプションは`WasmInstance`に保持し、`WasmFunction.Invoke`の呼び出しごとの実行オプション引数をなくす方針を採用した。既存のメソッドシグネチャは未実装の骨組みであり、この契約に合わせて変更する。

インスタンスは、自分が新たなWasm実行コンテキストを開くときに用いる上限値を実行ポリシーとして保持する。最外側のInvokeまたはstart実行でコンテキストを開いたインスタンスの上限を、そのコンテキストの寿命の間ずっと使う。内側で呼ばれたインスタンスの上限は参照せず、上限を差し替えたり最小値を選び直したりしない。

たとえば、上限100のAがコンテキストを開き、深さ50の位置から上限10のBを呼んでも、上限は100のままである。Bが単独で新たなコンテキストを開く場合は10を使う。呼び出し中のインスタンスの上限の最小値を採る案では、Bの上限を呼び出し連鎖全体へ途中から適用することになり、Aの深い位置からBを呼ぶだけで失敗する。この制約を避け、コンテキストの上限を1つの固定値として扱う方式を選んだ。

呼び出し深さは個々の`Invoke`ではなくWasm実行コンテキスト単位で共有する。同じ実行コンテキスト内で再度`Invoke`へ入っても深さを初期化しない。深さは呼び出しに入ると増え、戻ると減る値であり、終了済みの呼び出しも含む通算回数ではない。

現在のWasm実行コンテキストへの参照は`[ThreadStatic]`を付けたstaticフィールドに保持する。最外側のInvokeまたはstart実行がコンテキストを作り、同じスレッド上の同期的なネスト呼び出しは、ホストコールバックからの再呼び出しも含めて同じコンテキストを使う。最外側の正常終了・trap・ホスト例外のいずれでも`finally`で参照を解除し、ネストした呼び出しの終了時には外側のコンテキストを解除しない。深さも、例外による中断を含めて対応する呼び出しの分を戻す。

別スレッドの実行へ現在のコンテキストを引き継がず、非同期フローへの伝播は初期対象外とする。`[ThreadStatic]`はコンテキスト参照をスレッドごとに分離するためのもので、インスタンスやホストの共有状態への排他制御を提供しない。初期は単一スレッドでの同期実行を保証し、検証済みモジュールの共有や独立した別インスタンスの並行利用も含め、マルチスレッド利用の動作保証は対象外とする。関数呼び出しとホスト連携の具体的な実装は後続仕様が所有する。
