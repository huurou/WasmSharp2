# インスタンスの実行ポリシーでコンテキストを開き、最外側の上限を固定する

実行オプションは`WasmInstance`に保持し、`WasmFunction.Invoke`に呼び出しごとの実行オプション引数を設けない。ホスト関数の呼び出し時に与えるInstance引数は、対象へのアクセス情報として[ADR 0010](0010-host-function-instance-context.md)で定める。

インスタンスは、自分が新たなWasm実行コンテキストを開くときに用いる上限値を実行ポリシーとして保持する。定義関数への入口ではその所属instance、startの入口ではstartを持つinstanceの上限でコンテキストを開き、その寿命の間ずっと使う。startがホスト関数を指す場合も同じである。内側で呼ばれたinstanceやcallbackへ追加情報として渡すinstanceの上限へ切り替えず、上限を差し替えたり最小値を選び直したりしない。

進行中のWasm実行コンテキストがなく、C#からホスト関数を直接呼ぶ場合は、callbackの形式やInstance引数の指定だけでコンテキストを開かない。Instance引数はアクセス情報であり、実行ポリシーの選択には使わない。そこからWasm定義関数またはstartへ入った時点で開始し、そのWasm実行が終了した時点で解除する。

たとえば`H(instance: A)`がAのmemoryを読み書きするだけならコンテキストは作らない。HからBのWasm定義関数へ入ればBの上限を使い、AのWasm定義関数へ入ってその実行中にBも呼ぶ場合はAの上限を共有する。AのWasm実行が終了してHへ戻り、その後Bを呼ぶなら、Bへの入口で別のコンテキストをBの上限で開始する。ホスト関数Hの実行時間全体を一つのWasm実行とみなさない。

たとえば、上限100のAがコンテキストを開き、深さ50の位置から上限10のBを呼んでも、上限は100のままである。Bが単独で新たなコンテキストを開く場合は10を使う。呼び出し中のインスタンスの上限の最小値を採る案では、Bの上限を呼び出し連鎖全体へ途中から適用することになり、Aの深い位置からBを呼ぶだけで失敗する。この制約を避け、コンテキストの上限を1つの固定値として扱う方式を選んだ。

呼び出し深さは個々の`Invoke`ではなくWasm実行コンテキスト単位で共有する。既存コンテキスト内では、callbackがInstance引数を取るかどうかにかかわらずホスト関数も深さへ数え、再度`Invoke`へ入っても深さを初期化しない。深さは呼び出しに入ると増え、戻ると減る値であり、終了済みの呼び出しも含む通算回数ではない。Wasm実行コンテキスト外でのホストコード自身のCLR再帰を制限するものではない。

現在のWasm実行コンテキストへの参照は`[ThreadStatic]`を付けたstaticフィールドに保持する。コンテキストを開くWasm実行の入口が参照を設定し、同じスレッド上の同期的なネスト呼び出しは、ホストコールバックからの再呼び出しも含めて同じコンテキストを使う。開始したWasm実行の正常終了・trap・exhaustion・ホスト例外のいずれでも`finally`で参照を解除し、ネストした呼び出しの終了時には外側のコンテキストを解除しない。深さも、例外による中断を含めて対応する呼び出しの分を戻す。

別スレッドの実行へ現在のコンテキストを引き継がず、非同期フローへの伝播は初期対象外とする。`[ThreadStatic]`はコンテキスト参照をスレッドごとに分離するためのもので、インスタンスやホストの共有状態への排他制御を提供しない。初期は単一スレッドでの同期実行を保証し、検証済みモジュールの共有や独立した別インスタンスの並行利用も含め、マルチスレッド利用の動作保証は対象外とする。関数呼び出しとホスト連携の具体的な実装は後続仕様が所有する。
