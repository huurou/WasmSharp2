# 実行コンテキストを明示的に共有し、最外側の上限を固定する

実行オプションは`WasmInstance`に保持し、`WasmFunction.Invoke`に呼び出しごとの実行オプション引数を設けない。ホスト関数の呼び出し時に与えるInstance引数は、対象へのアクセス情報として[ADR 0010](0010-host-function-instance-context.md)で定める。

インスタンスは、自分が新たなWasm実行を始めるときに用いる上限値を実行ポリシーとして保持する。定義関数ではその所属instance、startではstartを持つinstanceの上限で内部状態を作り、その実行が終了するまで使う。startがホスト関数を指す場合も同じである。内側で呼ばれたinstanceやcallbackへ追加情報として渡すinstanceの上限へ切り替えず、上限を差し替えたり最小値を選び直したりしない。

指定コンテキストでWasmを実行しておらず、C#からホスト関数を直接呼ぶ場合は、callbackの形式やInstance引数の指定だけで内部状態を作らない。Instance引数はアクセス情報であり、実行ポリシーの選択には使わない。そこからWasm定義関数またはstartへ入った時点で内部状態を作り、そのWasm実行が終了した時点で解放する。

たとえば`H(instance: A)`がAのmemoryを読み書きするだけなら内部状態は作らない。HからBのWasm定義関数へ入ればBの上限を使い、AのWasm定義関数へ入ってその実行中にBも呼ぶ場合はAの上限を共有する。AのWasm実行が終了してHへ戻り、その後Bを呼ぶなら、同じコンテキストにBの上限で新しい内部状態を作る。ホスト関数Hの実行時間全体を一つのWasm実行とみなさない。

たとえば、上限100のAがコンテキストを開き、深さ50の位置から上限10のBを呼んでも、上限は100のままである。Bが単独で新たなコンテキストを開く場合は10を使う。呼び出し中のインスタンスの上限の最小値を採る案では、Bの上限を呼び出し連鎖全体へ途中から適用することになり、Aの深い位置からBを呼ぶだけで失敗する。この制約を避け、コンテキストの上限を1つの固定値として扱う方式を選んだ。

呼び出し深さは個々の`Invoke`ではなくWasm実行コンテキスト単位で共有する。既存コンテキスト内では、callbackがInstance引数を取るかどうかにかかわらずホスト関数も深さへ数え、再度`Invoke`へ入っても深さを初期化しない。深さは呼び出しに入ると増え、戻ると減る値であり、終了済みの呼び出しも含む通算回数ではない。Wasm実行コンテキスト外でのホストコード自身のCLR再帰を制限するものではない。

呼び出し元が`WasmExecutionContext`を保持し、`Invoke`と`Instantiate`の第1引数へ明示的に渡す。両形式のホストcallbackも同じオブジェクトを受け取り、同期再入ではそれを次の呼び出しへ渡す。スレッド上の暗黙の状態を参照する方式を改め、共有する呼び出し連鎖と状態の所有者を明確にする。別のオブジェクトを渡した呼び出しは独立した実行として扱う。

最外側のWasm実行の開始時に内部状態を生成し、正常終了・trap・exhaustion・ホスト例外のいずれでも`finally`で解放する。ネストした呼び出しでは外側の状態を維持し、深さも対応する呼び出しの分だけ戻す。同じ`WasmExecutionContext`を次の独立した呼び出しに再利用した場合は、その呼び出しを開始するinstanceのポリシーで新しい内部状態を作る。

コンテキストはスレッドや非同期フローへ暗黙に伝播せず、インスタンスやホストの共有状態への排他制御も提供しない。同じコンテキストの並行使用には対応せず、単一スレッドでの同期実行を保証する。検証済みモジュールの共有や独立した別インスタンスの並行利用も含め、マルチスレッド利用の動作保証は対象外とする。
