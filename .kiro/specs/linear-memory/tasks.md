# 実装タスク

## 実行上の前提

各タスクの`_Boundary:_`には、[設計](design.md)で定めた担当名を記載する。
各子タスクの作業時間は1〜3時間を目安とする。
準備段階では、対象の命令やセクションを未対応として扱う現在の動作を維持する。
デコード・検証・実行の処理が揃った統合タスクで、公開APIから利用できるようにする。
処理をせず成功だけを返す命令ハンドラーや、タスクを分割するためだけの公開APIは追加しない。

テストを追加・変更した場合は、先にReleaseビルドで警告とエラーがないことを確認し、対象テストをコマンドで実行する。
機能を公開APIへ接続する4.2・4.3・5.2・6.1・6.2では、その機能を未対応と期待する既存テストと対応済み命令一覧も更新する。
その後、Releaseビルドの成功を確認し、既存の3つのテストプロジェクトの全テストと、固定した版の公式テストスイート全体を実行する。

公式テストにはrunを使い、compare-runで統合先の先行機能について最後に明示保存された**実行結果baseline**と比較する。
実行結果baselineは、同じ公式ケースを再実行したときの比較基準であり、最終的な受入判定まで更新しない。
問題があれば実装を修正し、期待値や結果の分類を変更して合格させない。

並列に実施できる候補は3.1と3.2だけとする。
大項目1と2を完了してから着手し、この2タスクでは共通のテスト用データや補助コードを編集しない。
同じビルド出力を使う検証コマンドは、同時に実行しない。
