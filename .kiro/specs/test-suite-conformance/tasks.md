# 実装計画

各実行タスクは1〜3時間を目安とする。設計にある診断選択規則を通常入力へ適用し、責務整理の完了後に挙動を変更する。既存の公開契約、固定素材、ランナーの判定を維持する。

原因確認・修正・テスト結果は各担当タスクで修正記録へ対応付け、共通記録への反映は統合担当が行う。実装・テストの変更ごとにReleaseビルドの警告・エラー0を確認し、対象テストをコマンドで実行する。既存の対象メソッド別クラス・fixtureを優先し、TUnit、AAA、日本語の条件・期待結果名を使う。新規のテスト基盤や944件分の重複した単体テストは作らない。

`(P)`は明記した前提の完了後、直前の独立した作業と並行できるタスクを示す。同じ担当範囲内は記載順に進める。解析一式は同じ担当で扱い、共通fixture・修正記録への反映と共有ビルド出力を使うビルド・テストは直列化する。並列タスクは担当箇所とその専用テストに限定し、共通fixtureの変更が必要なら統合時に行う。

  - .NET 10、固定Core 2.0参照ソース、既存TUnitプロジェクト、ローカル整形ツールを利用可能にする。生成済み素材の実行にWABTのビルドを追加要求しない。
  - 通常のReleaseビルドが警告・エラー0で成功し、修正後の検証に使う通常ビルドのランナーを起動できる状態にする。

  - この段階では診断選択と検査順を変えず、通常入力の成功、未対応、破損の公開結果を維持する。

- [x] 3. 安全なバイナリ解析で参照診断を選択する
- [x] 3.1 整数と名前の符号化診断を合わせる
  - 固定規則と最小再現入力から原因を確認し、LEB128の表現長超過と最終payloadの値超過を設計の優先順位で区別する。
  - 符号付き・符号なし整数と狭い整数幅の共通読取りを整え、不正UTF-8は専用診断から始める。位置と補助説明は選択した原因に合わせる。
  - 許容payloadと継続bit、整数幅の境界、途中EOF、不正な名前の直接テストで、診断先頭と範囲安全性を確認する。
  - _Boundary: ModuleBinaryReader_
  - _Depends: 2.1, 2.2_
  - _Requirements: 1.2, 3.1, 3.2, 3.3, 3.5, 4.1, 4.2, 4.6_

- [x] 3.2 長さと要素数の共通読取りを利用箇所へ統合する
  - 名前・section・body・vectorの長さ読取りを、prefix前の位置から物理EOFまでの上限判定へ揃える。
  - reader・format・decoder・import調査への統合として、取得時の宣言範囲検査を保ち、長さ超過と要素不足を区別する。
  - 宣言数だけによる巨大な先行確保を避け、保持上限や一般資源不足をWasmの破損へまとめない。
  - prefix前後で残量が変わる入力、要素不足、宣言長の境界をテストし、既存のimport調査も成功・未確認範囲の契約を維持することを確認する。
  - 原因が変わる既存DecodeテストのLocation期待値を選択した原因に合わせて更新し、例外型・位置の検査を弱めない。
  - _Boundary: ModuleBinaryReader, ModuleBinaryFormat, ModuleDecoder, ImportInspector_
  - _Requirements: 2.4, 2.7, 3.1, 3.5, 4.4, 4.6_

- [x] 3.3 ヘッダーと共通バイナリ構造の診断を統合する
  - magicとversionをそれぞれ4byte取得後に照合し、途中EOF、完全な不一致、最初の相違位置を区別する。
  - limits flag、function/value/reference type、mutabilityの符号化診断を共通formatへ適用する。import/export kindはdecoderの呼出し文脈と共通処理の統合として診断を分ける。
  - 未知section IDと既知sectionの逆順・重複を区別し、後者は長さ・payloadより先に判定する。custom sectionで順序を進めない。
  - 0〜8byteのヘッダー、各符号化の境界、section順と不正payloadの複合入力で、期待する診断と位置が選ばれることを確認する。
  - _Boundary: ModuleBinaryFormat, ModuleDecoder_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 4.3, 4.4, 4.6_

- [x] 3.4 式終端・locals・function/codeの診断を合わせる
  - 式の停止とEND要求を分け、ELSE・END・EOFと宣言サイズの完了検査を区別する。
  - 圧縮local宣言は全件の符号化を確認後に合計上限を検査し、localを個別展開せず、後続宣言の符号化不正を優先する。
  - function/codeの件数不一致を対応する診断にし、宣言件数から確定する既存の早期検査を維持する。後続の未対応命令を調べるために検査を遅らせない。
  - 終端、複数local宣言、件数不一致と未対応命令の複合入力で、先行機能内の原因が期待どおり選ばれることを確認する。
  - _Boundary: ModuleDecoder_
  - _Requirements: 2.3, 2.4, 3.1, 3.4, 4.4, 4.5, 4.6_

- [x] 3.5 診断専用の読取りと範囲完了検査を統合する
  - 確定済み境界失敗後の診断用モードに、物理入力内での読取りと独立した宣言終端の追跡を実装する。
  - 子reader作成時の親の先送りを宣言長基準とし、物理EOFを超えないようにする。完了時には現在位置と宣言終端の一致を要求する。
  - readerと共通formatの範囲完了検査を統合し、診断用モードでは内部境界通知を発生させない。
  - 境界をまたぐLEB・名前長、過大な宣言サイズ、物理EOFの直接テストで、公開Decode診断への確定と範囲外アクセスの不発生を確認する。
  - _Boundary: ModuleBinaryReader, ModuleBinaryFormat_
  - _Requirements: 2.4, 3.4, 3.5, 4.2, 4.5, 4.6_

- [x] 3.6 一度だけの診断再走査を公開Decodeへ統合する
  - 通常解析が境界不正を確定した場合だけ、共通の構文処理を診断用モードで1回呼び出す。得られた構文診断を選び、未対応・実装上限・正常終了なら元の範囲不正を公開する。
  - 宣言残量を使うcustom payloadの読み飛ばしを適用し、宣言外を含む物理残量の一括消費を防ぐ。名前取得後の残量が負なら`unexpected end of section or function`を通知し、RequireEndへ進めない。custom.wast#5と同じ構造の最小入力で確認する。
  - 再走査で得たmoduleを返さず、通常の未対応・ホスト例外・一般資源不足・予期しない例外を包括的に捕捉して読み替えない。
  - reader・format・decoder・import調査の統合確認として、END欠落後のELSE・EOF・後続section、境界をまたぐ整数と名前長で診断が分かれ、正常入力の再解析や再帰的な再走査がないことを確認する。
  - 公開例外へ内部通知が漏れず、import調査は全moduleの再Decodeを要求せずに完全一覧・未確認範囲を返すことを確認する。
  - _Boundary: ModuleBinaryReader, ModuleBinaryFormat, ModuleDecoder, ImportInspector_
  - _Requirements: 2.3, 2.4, 2.7, 3.4, 3.5, 3.6, 4.5, 4.6_
